# MatchTrak Helper — Chrome Extension

Chrome MV3 content script that injects a **Lifetime Stats** table into MatchTrak referee profile pages (`matchtrak.com/*/referee.nsf/open*`). It parallel-fetches all archived-month pages, aggregates game counts by Role × Age-Group, and caches results in `chrome.storage.local`.

## Key files

| File | Purpose |
|---|---|
| `src/parser.ts` | Pure parsing logic — no DOM side-effects; fully unit-tested |
| `src/content.ts` | Content script — fetches, caches, renders; not unit-tested (depends on Chrome APIs) |
| `src/types.ts` | Shared TypeScript types (`Role`, `Bucket`, `GameRow`, etc.) |
| `src/styles.css` | Scoped CSS injected by the manifest (no build step needed) |
| `dist/content.js` | Compiled output — generated by `npm run build`, never edit directly |
| `manifest.json` | MV3 manifest — URL matches, permissions, entry points |

## Commands

```bash
npm run build       # compile src/ → dist/content.js (required before reloading in Chrome)
npm run dev         # watch mode — recompiles on save
npm test            # Jest unit tests for parser.ts
npm run type-check  # tsc --noEmit
npm run lint        # ESLint
npm run package     # build + zip for Chrome Web Store submission
```

Pre-commit: `npm run type-check && npm test && npm run lint && npm run build`

## Architecture notes

- Single content script entry point: `src/content.ts` → `dist/content.js`
- `parser.ts` has zero browser/Chrome API dependencies — keep it that way so tests stay easy
- `content.ts` is manually tested by loading the unpacked extension in Chrome and visiting a MatchTrak profile page; console logs under the `[MTHelper]` prefix
- No data leaves the device — all fetches go to `matchtrak.com`; cache lives in `chrome.storage.local`
